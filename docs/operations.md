# 運用手順書

## 1. 導入

### 1.1 前提
- Windows 10 / 11、Microsoft 365 または Excel 2016 以降のデスクトップ版
- ブックを置くフォルダは、OneDrive などの同期フォルダを避ける（ブックのパスが URL になり、ファイル操作が失敗するため）

### 1.2 配置
1. [Releases](https://github.com/KoichiKurita/VBA-Order-Automation/releases/latest) から `OrderTool.xlsm` をダウンロードし、任意のフォルダ（例：`C:\OrderTool`）に置く
2. ブックを右クリック → プロパティ → 「許可する」にチェック（インターネットから取得したファイルのマクロ無効化を解除）
3. （推奨）Excel のトラストセンターで、このフォルダを「信頼できる場所」に登録する
4. 自動実行を使う場合は、`scripts` フォルダもブックと同じ場所に置く

### 1.3 初期設定
1. ブックを開くと、メニューが表示される
2. 「**初期設定（最初に1回だけ）**」を押す
   - 押した人が管理者（ADMIN）として登録される
   - シート保護のパスワードが乱数で生成され、各シートが保護される
3. 他の利用者を登録する（「2.6 ユーザー管理」）

## 2. 日常の運用

### 2.1 受注CSVの取込
1. メニューの「受注CSVを取り込む」を押し、CSVを選ぶ
2. 結果が表示される
   - エラーがなければ Orders シートに追加される
   - エラーがあれば ImportErrors シートに「CSV行番号・列名・値・エラー内容」が表示される
3. エラーがあった場合は、CSVを修正して同じファイルをもう一度取り込む
   - 既定（ALL_OR_NOTHING）では、1件でもエラーがあると何も取り込まれないため、修正後にそのまま再取込できる
   - 取込済みの受注番号は自動で重複エラーになるため、二重に取り込まれることはない

| よくあるエラー | 対応 |
|---|---|
| 必須項目が未入力です | 該当の列に値を入れる |
| 形式が不正です（例：…） | 例の形式に合わせる（受注番号・顧客コード・商品コード） |
| 正しい日付（yyyy/mm/dd）で入力してください | 存在する日付を `2026/11/07` の形式で入れる |
| 数値で入力してください（桁区切りのカンマは不可） | `1,200` を `1200` にする |
| 列数が一致しません | 項目の過不足を確認する（値にカンマを含む場合は `"` で囲む） |
| 取込済みのデータと重複しています | すでに取り込まれている。再取込の必要はない |
| 数式として解釈される文字で始まっています | 先頭の `=` `+` `-` `@` を取り除く（REJECT 設定の場合） |

### 2.2 レポートの作成
1. メニューの「月次レポートを作成する（PDF / CSV）」を押す
2. 集計する年月（既定は最新の受注月）を入力する
3. `output` フォルダに PDF と CSV が作成される

### 2.3 取込の取消（管理者）
誤ったファイルを取り込んだ場合は、メニューの「直近の取込を取り消す」を押す。
取込ID・ファイル名・件数を確認してから「はい」を押す（既定のボタンは「いいえ」）。取消の前に自動でバックアップされる。

### 2.4 設定の変更（管理者）
1. メニューの「設定（Config・Schema）を編集する」を押す（保護が外れる）
2. Config・Schema を編集する
3. 「シート保護を再設定する」を押す（保存時にも自動で保護される）

Schema に項目を追加・変更した場合は、既存の Orders シートと列構成が合わなくなるため、Orders シートの名前を変更して退避してから取り込む。

### 2.5 ユーザー管理（管理者）
1. メニューの「ユーザーを管理する」を押す（_Users シートが表示される）
2. 行を追加・変更する

| 列 | 内容 |
|---|---|
| UserName | Windows のログオン名（コマンドプロンプトで `whoami` の `\` の後ろ）。`*` で未登録の全員 |
| Role | ADMIN（管理者）/ OPERATOR（担当者）/ VIEWER（閲覧者） |
| Enabled | TRUE / FALSE（FALSE にすると利用できなくなる。退職者は行を消さず FALSE にする） |

3. 「シート保護を再設定する」を押す

| 操作 | VIEWER | OPERATOR | ADMIN |
|---|:---:|:---:|:---:|
| レポートの作成 | ○ | ○ | ○ |
| CSVの取込 |  | ○ | ○ |
| 取込の取消・設定の変更・ユーザー管理・監査ログの検証 |  |  | ○ |

- 有効な管理者が1人もいなくなる変更は、保存・保護の再設定ができないようになっている
- `*` に ADMIN は設定できない（OPERATOR に制限される）

## 3. 自動実行

### 3.1 フォルダ

| フォルダ | 内容 |
|---|---|
| `batch\inbox` | 取り込む CSV を置く |
| `batch\processed\yyyymm` | 取り込んだ CSV（先頭に実行IDが付く） |
| `batch\error` | エラーになった CSV と、エラー一覧（`…_errors.csv`） |

### 3.2 登録・停止
```powershell
# 毎日 7:00 に実行するよう登録（ログオン中のみ実行）
.\scripts\register_task.ps1 -Time 07:00

# すぐに試す
Start-ScheduledTask -TaskPath "\VBA-Order-Automation\" -TaskName "DailyOrderImport"

# 登録を削除する
Unregister-ScheduledTask -TaskPath "\VBA-Order-Automation\" -TaskName "DailyOrderImport" -Confirm:$false
```

- 実行時刻に誰かがブックを開いていると、異常終了（終了コード2）になる。業務時間外に設定する
- 本番では、バッチ専用のアカウントを OPERATOR として登録し、必要最小限の権限で動かす

### 3.3 結果の確認

| 終了コード | 状態 | 対応 |
|---:|---|---|
| 0 | OK | なし |
| 1 | WARN（一部のファイルがエラー） | `batch\error` のエラー一覧を確認し、CSVを直して `batch\inbox` に戻す |
| 2 | ERROR（異常終了） | アプリログ・`logs\launcher.log` を確認する |
| 3 | SKIPPED（前回のバッチが実行中） | 続く場合は `logs\batch.lock` が残っていないか確認する（60分で自動的に無効） |

結果は次の場所にも記録される。
- `output\batch\batch_<実行ID>.json`
- Windows のイベントログ（イベントビューアー → Windows ログ → アプリケーション、ソース「WSH」）

### 3.4 Webhook 通知（任意）
1. Slack または Discord で Webhook の URL を発行する
2. URL を**環境変数**に設定する（ブックやソースには書かない）
   ```powershell
   setx ORDERTOOL_WEBHOOK_URL "https://..."
   ```
3. Excel を再起動し、Config の `NotifyWebhookFormat`（SLACK / DISCORD）と `NotifyOn`（ALWAYS / ERROR / NONE）を設定する
4. VBE で `TestNotification` を実行して確認する

## 4. 障害対応

### 4.1 問い合わせ番号からログを調べる
エラー画面に表示された問い合わせ番号（例：`20261126-010511-0648`）でログを検索する。
```powershell
Select-String -Path logs\*.log -Pattern "20261126-010511-0648" -Encoding 932
```

### 4.2 よくある障害

| 現象 | 原因と対応 |
|---|---|
| マクロが動かない | ファイルのブロック（プロパティ →「許可する」）、または信頼できる場所への登録を確認する |
| 「ユーザー登録がありません」 | 管理者に _Users への登録を依頼する |
| 「シートの保護を解除できません」 | 手作業で別のパスワードで保護された可能性。管理者が「シート保護を再設定する」を実行する |
| 「Ordersシートの列構成がSchemaと一致しません」 | Schema を変更した。Orders シートの名前を変えて退避してから取り込む |
| バッチが毎回 SKIPPED | 異常終了したバッチの `logs\batch.lock` が残っている（60分後に自動で無効。急ぐ場合は削除） |
| バッチ後に Excel が残る | 通常は数秒で終了する。残り続ける場合はタスクマネージャーで終了し、`logs\launcher.log` を確認する |

## 5. バックアップと復元
- 取込・取消の前に `backup` フォルダへ自動でバックアップされる（既定で10世代）
- 復元するときは、Excel を閉じてから、バックアップのファイルを `OrderTool.xlsm` という名前でコピーして置き換える
- 復元したことは、監査ログに残らないため、運用記録に残しておく

## 6. ログ

| ファイル | 内容 | 保持 |
|---|---|---|
| `logs\app_yyyymmdd.log` | 処理の記録（INFO / WARN / ERROR） | 30日（Config の LogRetentionDays） |
| `logs\audit.log` | 監査ログ（誰が・いつ・何をしたか） | 自動削除しない |
| `logs\launcher.log` | 自動実行の起動結果 | 自動削除しない |

ログは Shift_JIS で書かれる。PowerShell 7 で読むときは `-Encoding 932` を付ける。

## 7. 監査
- 管理者は、定期的にメニューの「監査ログを検証する」を実行する
- 「ハッシュが一致しません」と表示された場合は、その行またはその直前の行が書き換え・削除された可能性がある。`audit.log` のバックアップと照合し、経緯を調査する
- 記録される操作：初期設定、ブックを開く、取込、取消、レポート作成、PDF・CSV出力、権限のない操作の試行、保護の解除・再設定、ユーザー管理、監査ログの検証、バッチ、配布用ブックの作成

## 8. リリース手順（開発者）
1. `modVersion` の `APP_VERSION` を更新する
2. `RunAllTests` を実行し、すべて PASS することを確認する
3. `PrepareRelease` を実行する（`dist\OrderTool.xlsm` に配布用のブックができる）
4. 配布用のブックを開き、VBE で次を行って保存する
   - ツール → VBAProject のプロパティ → 保護 → 「プロジェクトを表示用にロックする」（パスワードはパスワード管理ツールで保管し、リポジトリには置かない）
   - ツール → デジタル署名 → コード署名用の証明書を選ぶ
5. Git のタグを作成し、GitHub のリリースに `dist\OrderTool.xlsm` とサンプルCSVを添付する

デジタル署名の証明書は、本番では認証局（CA）が発行したコード署名証明書を使う。
開発・検証用には自己署名の証明書を使い、検証する PC の「信頼されたルート証明機関」と「信頼された発行元」に登録する。
