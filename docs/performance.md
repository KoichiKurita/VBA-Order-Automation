# 性能（非機能要件）

## 目標

| 処理 | 条件 | 目標 |
|---|---|---|
| 取込（読込・検証・書込・バックアップ） | 受注CSV 10万行（約11MB） | 30秒以内 |
| 集計・帳票作成 | 受注データ 10万行 | 10秒以内 |

## 計測方法

- `modPerfTest.RunPerformanceTest` を実行すると、テストデータの生成から取込・集計・取消までを自動で計測する
- テストデータは乱数の種を固定して生成するため、何度でも同じデータで再計測できる
- 同じ条件でも1回ごとに数秒ぶれるため、3回計測して**中央値**で判定する
- 時間は Windows API（QueryPerformanceCounter）で計測し、処理を区間に分けてログに記録する
- 取込の部品ごとの時間は、診断用マクロ `modProfile.ProfileImport` で計測する

## 改善の経緯

推測で直すのではなく、**区間ごとに計測 → 最も遅い区間の原因を特定 → 改善 → 再計測**をくり返した。

| 区間 | 改善前 | 1回目 | 2回目 | 3回目 |
|---|---:|---:|---:|---:|
| 読込（文字コード判定・変換） | 27.90秒 | 39.99秒 | 0.29秒 | 0.27秒 |
| パース | 10.78秒 | 7.37秒 | 3.40秒 | 3.04秒 |
| 検証 | 47.85秒 | 39.84秒 | 13.58秒 | 11.85秒 |
| セル書込 | 26.60秒 | 28.96秒 | 14.59秒 | 15.00秒 |
| その他（エラー出力・バックアップ等） | 2.89秒 | 3.19秒 | 1.33秒 | 2.15秒 |
| **取込合計** | **117.19秒** | **120.47秒** | **33.81秒** | **32.93秒** |

### 1回目：読込・パース・検証の改善

| 区間 | 見立て | 対策 | 結果 |
|---|---|---|---|
| 読込 | 文字コード判定のため、11MBをVBAで1バイトずつ検査している | 検査を先頭1MBに限定 | **悪化**（見立てが外れた） |
| パース | 全文字を1文字ずつ処理している | 引用符のない行は `Split` で一括分割 | 10.8秒 → 7.4秒 |
| 検証 | 全角→半角変換を毎回行っている、範囲の比較値を毎回型変換している | 変換は失敗時だけ、比較値は事前に変換 | 47.9秒 → 39.8秒 |

読込が速くならなかったことで、本当の原因は判定ではなく、文字コード変換に使っていた `ADODB.Stream` だと分かった（11MBを一括変換すると極端に遅い）。

### 2回目：原因を特定したうえでの改善

| 区間 | 原因（計測で判明） | 対策 | 結果 |
|---|---|---|---|
| 読込 | `ADODB.Stream` による文字コード変換が遅い | Windows API `MultiByteToWideChar` で判定・変換（ファイル全体を正確に検査したまま） | 40.0秒 → **0.29秒** |
| 検証 | 内容が空の「備考」でも10万件で0.7秒かかる → 処理内容よりも関数呼び出し（100万回）の負担が大きい | 列単位の一括検証に変更し、関数呼び出しを「セル数」回から「列数」回に。正常な値は近道で通し、エラーの疑いがある値だけ詳細なチェックへ | 39.8秒 → 13.6秒 |
| セル書込 | 先頭に `'` を付けた文字列の書込が遅い | 文字列項目の列を `@`（文字列書式）にしてから、そのまま書き込む。数式が評価されないことを `ProfileImport` で確認してから採用 | 29.0秒 → 14.6秒 |

### 3回目：残りの細かい改善

- CSVインジェクションの判定を、1セルずつではなく列単位で実施
- 重複チェックの Dictionary を1つにまとめ、照会回数を削減

効果は1秒前後で、計測のぶれ（同条件で約5秒）より小さかった。ここで「1回だけの計測では比較できない」と判断し、計測を3回の中央値に変更した。

## 判断

改善前の117秒から約33秒（**約3.5倍の高速化**）となったが、目標の30秒には届いていない。

- 残りの時間の約半分（約15秒）は、Excel が130万セルを書き込む時間で、VBA側では大きく削れない
- さらに短縮するには、取込日時・ファイル名を別の「取込履歴」表に分けて書き込むセルを減らす方法がある（約2～3秒の短縮見込み）。ただし Orders の列構成が変わり、影響範囲が広がる
- 計測したPCのCPUは2012年ごろの世代（Intel 第3世代 Core）で、現在の一般的なPCより処理性能が低い

以上から、**今回の改善はここで区切り**、計測環境とあわせて結果を記録する。取込履歴表への分割は、今後の改善候補とする。
